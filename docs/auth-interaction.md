# 注册登录业务交互文档

## 1. 目标与范围

本期为 Wex 增加注册、登录和退出登录的完整访问闭环，并根据用户登录状态调整首页与工作台的入口。

覆盖范围：

- 首页右上角的登录入口与登录用户头像。
- 首页“进入工作台”按钮的登录态分流。
- 登录页面的 Email/Password 自动登录/注册分流、邮箱确认流程、Google OAuth 跳转、提交反馈和成功跳转。
- 工作台右上角头像及“退出登录”菜单。
- 工作台的登录访问限制和退出后的页面跳转。

暂不包含找回密码、个人资料编辑、头像上传和多账号切换。邮箱确认只用于首次注册，不作为找回密码流程。

## 2. 名词与登录状态

| 状态           | 定义                                 | 页面表现                                                       |
| -------------- | ------------------------------------ | -------------------------------------------------------------- |
| 登录状态确认中 | 应用启动后正在恢复本地会话           | 不展示会引起误操作的登录入口或账户菜单；受保护页面保持加载状态 |
| 未登录         | 不存在有效用户会话                   | 首页展示“登录”；访问工作台时进入登录页                         |
| 已登录         | 存在有效用户会话且可取得当前用户信息 | 首页和工作台展示头像；允许进入工作台                           |
| 会话失效       | 原会话过期、被撤销或校验失败         | 清除本地登录状态，并按未登录流程处理                           |

认证流程状态：

| 状态         | 进入条件                           | 页面表现                                                                       |
| ------------ | ---------------------------------- | ------------------------------------------------------------------------------ |
| 凭证填写中   | 初次打开认证页或返回凭证步骤       | 展示邮箱、密码和主操作；允许切换 Google OAuth                                  |
| 邮箱确认中   | 确认账号未注册，并成功发出确认邮件 | 保留脱敏邮箱和一次性密码上下文，展示查收邮件提示、重新发送倒计时和返回修改入口 |
| OAuth 跳转中 | 点击 Google 登录后已发起跳转       | 禁用认证操作并展示处理中状态，避免重复创建 OAuth 请求                          |
| 认证错误     | Supabase 返回错误或确认链接失效    | 停留在当前步骤，展示可理解错误并允许重试                                       |

头像首期无需支持上传。用户有头像地址时展示头像图片；没有头像地址时展示默认账户图标或用户名/邮箱首字符，且必须提供可访问名称“账户菜单”。

## 3. 页面与路由

| 页面   | 路由                   | 访问规则                                       |
| ------ | ---------------------- | ---------------------------------------------- |
| 首页   | `/`                    | 所有人可访问，根据登录状态展示不同的右上角操作 |
| 登录页 | `/auth`                | 未登录用户可访问；系统自动识别登录或首次注册   |
| 工作台 | `/workspace`           | 仅登录用户可访问                               |
| 项目页 | `/projects/:projectId` | 与工作台保持一致，仅登录用户可访问             |

认证页建议使用以下地址表达初始模式和登录后的返回目标：

```text
/auth?redirect=/workspace
```

`redirect` 只允许使用站内路径，非法值或缺失时统一回退到 `/workspace`，避免跳转到外部地址。

## 4. 核心业务流程

### 4.1 首页右上角

#### 未登录

- 右上角展示一个“登录”按钮。
- 点击后进入 `/auth`。
- 首页不展示头像或账户下拉菜单。

#### 已登录

- 隐藏“登录”按钮，原位置展示当前用户头像。
- 点击头像打开账户下拉菜单。
- 下拉菜单首期只有“退出登录”一个选项。
- 再次点击头像、点击菜单外部或按 `Escape` 关闭菜单。

### 4.2 首页“进入工作台”按钮

该按钮对应当前 `apps/web/src/pages/home-page.tsx` 中的首页主操作。

| 用户状态       | 点击结果                           |
| -------------- | ---------------------------------- |
| 已登录         | 直接进入 `/workspace`              |
| 未登录         | 进入 `/auth?redirect=/workspace`   |
| 登录状态确认中 | 按钮暂时禁用，确认完成后再允许操作 |

用户由此入口完成登录或注册后，进入原目标 `/workspace`，不再返回首页要求用户重复点击。

### 4.3 直接访问工作台

- 已登录用户访问 `/workspace` 时正常展示工作台。
- 未登录用户访问 `/workspace` 时进入 `/auth?redirect=/workspace`。
- 登录状态确认期间不提前渲染工作台数据，避免受保护内容闪现。
- 会话失效时按未登录处理，并保留当前站内目标作为 `redirect`；重新登录后返回原目标。

项目页采用相同规则。例如未登录用户访问 `/projects/123`，应进入登录页，成功后返回 `/projects/123`。

## 5. 登录页交互

### 5.1 页面结构

- 左上角展示 Wex 品牌入口，点击返回首页。
- 页面主体只提供一个 Email/Password 表单，不要求用户预先选择登录或注册。
- 页面保留合法的 `redirect`；非法或缺失时回退到 `/workspace`。
- 邮箱确认步骤所需的密码只允许短暂保存在当前页面内存中，不写入 URL、LocalStorage 或日志；返回修改邮箱或离开认证页时立即清除。
- 已登录用户进入 `/auth` 时直接前往合法的 `redirect`，没有合法目标则进入 `/workspace`。

### 5.2 认证方式选择

认证页提供两种登录方式，二者共用同一个 `redirect`：

1. **Supabase Auth + Email/Password**：输入邮箱和密码。系统先检查该邮箱是否已有账号；已注册则直接使用密码登录，未注册则发送确认邮件，点击邮件中的确认链接后创建账号并登录。
2. **Supabase Auth + Google OAuth**：点击“使用 Google 登录”后跳转 Google 授权页，完成授权后回到应用回调地址，再进入工作台。

两种方式都必须在服务端或 Supabase Auth 层建立有效会话后才算成功，前端不能仅凭页面跳转判定已登录。

### 5.3 Email/Password 登录与注册

表单字段：

| 字段 | 规则                               |
| ---- | ---------------------------------- |
| 邮箱 | 必填；去除首尾空格；按邮箱格式校验 |
| 密码 | 必填；按产品密码强度规则校验       |

操作规则：

- 主按钮文案固定为“登录”。系统自动执行下述账号检查与邮箱确认分流；提交中禁用表单与重复提交，支持字段有效时按 `Enter` 提交。
- 第一步先规范化邮箱（去除首尾空格并按统一规则转小写），再调用账号存在性检查。
- 检查结果为已注册：调用 Supabase Auth 的密码登录；成功建立会话后只跳转一次到合法 `redirect`，默认 `/workspace`。失败时停留在凭证步骤，展示“邮箱或密码错误”，不泄露具体账号状态。
- 检查结果为未注册：调用 Supabase Auth 发送邮箱确认邮件。成功后进入“邮箱确认中”，不跳转工作台。
- 邮箱确认步骤展示脱敏邮箱（例如 `a***@example.com`）、查收邮件和点击确认链接的提示、重新发送倒计时和“返回修改邮箱”入口。
- 用户点击邮件确认链接后回到 `/auth/callback`，应用由 Supabase 交换会话；成功后进入合法 `redirect`，默认 `/workspace`。
- 确认链接失效、已使用或网络失败时停留在确认步骤，保留已输入邮箱并允许重新发送邮件。
- 邮箱、密码格式不合法或网络失败时，在对应字段或表单区域给出错误提示；允许用户修正后重试。重新发送邮件必须受倒计时限制，不能重复触发请求。

账号存在性检查属于认证流程内部步骤；接口响应不得直接暴露给未授权客户端，避免被用于批量枚举账号。

### 5.4 Google OAuth

- 认证页展示“使用 Google 登录”按钮，按钮进行中时禁用自身及其他认证提交。
- 点击后调用 Supabase Auth OAuth 登录，并指定 `provider: 'google'`、应用回调地址和合法 `redirect`（通过受保护的 `state` 保存，不把未校验的外部地址写入回调）。
- 浏览器跳转到 Google 授权页。用户取消授权或 Google 返回错误时回到 `/auth`，恢复凭证填写步骤并展示“Google 登录已取消”或“Google 登录失败，请重试”。
- 授权成功后回到应用回调路由（例如 `/auth/callback`）。回调路由校验 OAuth `code/state`，由 Supabase 交换会话，确认当前用户信息后再跳转一次到合法 `redirect`，默认 `/workspace`。
- 回调期间不得短暂展示未登录首页或受保护数据；会话交换失败时清理临时参数并回到 `/auth`，保留可重试入口。
- 已有相同邮箱的 Supabase 用户由 Supabase 账号关联策略处理；页面只展示最终成功或失败结果，不自行创建重复账号。

## 6. 头像菜单与退出登录

### 6.1 菜单行为

- 首页和工作台复用相同的头像与账户菜单交互。
- 菜单相对头像向下对齐，不遮挡头像，层级高于页面主体内容。
- 菜单只有“退出登录”一项；该操作应使用清晰的退出图标与文字。
- 菜单支持鼠标和键盘操作。打开后可聚焦“退出登录”，按 `Escape` 关闭并将焦点还给头像按钮。

### 6.2 退出登录

- 点击“退出登录”后立即关闭菜单，并进入退出处理中状态，防止重复点击。
- 退出成功后清除当前会话和用户信息。
- 无论从首页还是工作台退出，成功后统一回到首页 `/`。
- 首页随即展示“登录”按钮，不再展示头像。
- 退出请求失败时保留当前登录状态，并展示“退出失败，请重试”的非阻塞提示。
- 退出后使用浏览器后退返回工作台或项目页时，路由守卫仍需拦截并进入登录页，不能依赖页面历史绕过鉴权。

## 7. 页面状态矩阵

| 页面/操作         | 未登录                                               | 已登录                        |
| ----------------- | ---------------------------------------------------- | ----------------------------- |
| 首页右上角        | “登录”按钮                                           | 头像与账户菜单                |
| 首页“进入工作台”  | 前往登录页，成功后进入工作台                         | 直接进入工作台                |
| 访问 `/auth`      | 展示登录页面及 Email/Password、Google OAuth 两种方式 | 跳转工作台或合法的 `redirect` |
| 访问 `/workspace` | 前往登录页并记录目标                                 | 正常访问                      |
| 访问项目页        | 前往登录页并记录目标                                 | 正常访问                      |
| 点击“退出登录”    | 不展示该操作                                         | 清除会话并回到首页            |

## 8. 异常与边界处理

- 网络断开：登录、注册、确认邮件发送或退出失败时保留可恢复的当前页面状态，并允许重试。
- 会话过期：下一次会话校验或受保护 API 返回未授权时，统一清除无效会话并进入登录流程。
- 多标签页：一个标签页登录或退出后，其他标签页应同步更新认证状态；退出后不得继续展示受保护数据。
- 连续点击：登录、注册和退出请求进行中均禁止重复提交。
- 页面刷新：刷新后先恢复会话，再决定展示“登录”、头像或受保护页面。
- 返回目标：认证失败、邮箱确认步骤和 OAuth 回调失败均不丢失合法的 `redirect`；认证成功只跳转一次。
- OAuth 安全：回调必须校验 `state` 与 `code`，拒绝状态不匹配、重复消费或过期的回调参数。
- 受保护 API：前端路由限制只负责交互体验，工作台和项目相关 API 仍必须在服务端校验用户身份及资源归属。

## 9. 验收标准

1. 未登录打开首页时，右上角只展示“登录”，点击可进入登录页。
2. 未登录点击首页“进入工作台”时进入登录页，登录成功后自动进入工作台。
3. 已登录点击首页“进入工作台”时直接进入工作台。
4. 已登录打开首页时不展示“登录”，右上角展示头像。
5. 首页和工作台点击头像均能打开只包含“退出登录”的菜单，并可通过外部点击和 `Escape` 关闭。
6. 点击“退出登录”成功后回到首页，头像被“登录”替换。
7. 未登录直接访问工作台或项目页时会进入登录页，登录成功后回到原目标。
8. 页面刷新时不会短暂展示错误的登录态 UI 或受保护内容。
9. Email/Password 已注册账号可直接登录；未注册账号会收到确认邮件，点击确认链接后建立会话并进入工作台。
10. 确认邮件发送失败、链接失效、重发倒计时和网络异常均有明确反馈，且不能重复提交。
11. Google 登录可跳转授权页，授权回调成功后建立会话并进入工作台；取消或失败可回到登录页重试。
12. 登录、注册和退出均具备进行中、成功与失败反馈，且进行中不能重复提交。
13. 退出后无法通过浏览器后退直接重新进入工作台或项目页。
