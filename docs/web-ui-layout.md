# Wex Web UI 布局设计

## 1. 文档目标

本文定义 Wex 建站产品第一阶段的前端信息架构与页面布局，作为后续在 `apps/web` 中实现 UI 的基础。

本阶段只覆盖三个核心页面和最短操作链路：

```text
首页 -> 工作台 -> 新建项目 -> 项目编辑器
                 项目卡片 -> 项目编辑器（后续接入）
```

暂不纳入第一阶段：登录注册、团队协作、模板市场、文件树、版本历史、发布流程、计费和项目设置。

## 2. 产品与视觉方向

- 产品定位：面向高频创作的 AI 建站工作台。
- 体验关键词：安静、直接、专业、可持续长时间使用。
- 布局原则：项目编辑器优先占满视口，让对话和产物预览成为两个并列的主要工作区。
- 视觉原则：使用中性背景、清晰边界和少量状态色；避免营销页式的大卡片堆叠与装饰性渐变。
- 交互原则：常用操作始终可见；拖拽调整布局时不改变页面整体尺寸。

## 3. 路由与页面层级

建议路由如下：

| 页面       | 路由                   | 作用                                |
| ---------- | ---------------------- | ----------------------------------- |
| 首页       | `/`                    | 产品入口，提供进入工作台的主操作    |
| 工作台     | `/workspace`           | 查看与创建项目                      |
| 项目编辑器 | `/projects/:projectId` | 通过聊天生成内容并查看 Sandbox 预览 |

当前 `apps/web` 未安装路由库。实现阶段建议引入 React Router；如果 MVP 暂时只做静态原型，也可先用顶层页面状态模拟导航，但页面组件仍应按上述路由边界拆分。

## 4. 页面布局

### 4.1 首页

首页首屏只承担品牌识别和进入工作台，不展示复杂的产品介绍。

```text
+------------------------------------------------------------------+
| Wex                                                   [状态/账户] |
|                                                                  |
|                                                                  |
|                         WEX                                      |
|                  用对话构建你的站点                              |
|                                                                  |
|                    [进入工作台 ->]                               |
|                                                                  |
|                                                                  |
+------------------------------------------------------------------+
```

布局要求：

- 顶部导航高度 `56px`，左右内边距桌面端 `32px`、移动端 `16px`。
- 主内容在剩余视口内居中，但底部保留空间，让页面不呈现为封闭卡片。
- `进入工作台` 是页面唯一主按钮，点击进入 `/workspace`。
- 首屏最小高度为 `100dvh`；不依赖滚动才能看到主按钮。

### 4.2 工作台

工作台是项目管理入口。第一阶段即使没有真实项目数据，也应保留完整的标题区、创建入口和空状态。

```text
+------------------------------------------------------------------+
| Wex / 工作台                                         [账户菜单]  |
+------------------------------------------------------------------+
|                                                                  |
|  项目                                          [+ 创建项目]      |
|  管理你创建的网站                                                |
|                                                                  |
|  +------------------------------------------------------------+  |
|  |                                                            |  |
|  |                   暂无项目                                 |  |
|  |                 [+ 创建第一个项目]                          |  |
|  |                                                            |  |
|  +------------------------------------------------------------+  |
|                                                                  |
+------------------------------------------------------------------+
```

布局要求：

- 复用首页顶部导航，内容最大宽度建议为 `1200px`。
- 页面标题和 `创建项目` 按钮处于同一操作栏；窄屏时上下排列。
- 有项目时使用响应式网格展示项目卡片，建议桌面端 3 列、平板 2 列、移动端 1 列。
- 项目卡片后续可包含名称、预览缩略图、更新时间和更多操作菜单。
- 点击 `创建项目` 后，MVP 可直接创建默认项目并进入 `/projects/:projectId`；接入真实项目字段后再增加创建对话框。
- 创建中需要禁用按钮并显示进度，防止重复创建。

### 4.3 项目编辑器

项目编辑器使用全视口双栏，不再沿用首页和工作台的全局顶部导航。项目级导航放入左侧聊天区顶部，以尽可能扩大预览面积。

```text
+-------------------------------+|+--------------------------------+
| <- 工作台   项目名称       ... |||  Preview              [刷新]  |
+-------------------------------+|+--------------------------------+
|                                |||                                |
|  对话消息                      |||                                |
|                                |||       Sandbox Preview          |
|  用户：创建一个首页            |||                                |
|                                |||                                |
|  Agent：正在生成...            |||                                |
|                                |||                                |
|                                |||                                |
+-------------------------------+|+                                |
| [描述你想创建或修改的内容...]  |||                                |
|                         [发送] |||                                |
+-------------------------------+|+--------------------------------+
        Chat Panel               ^          Preview Panel
                              Resize Bar
```

编辑器根容器：

- 宽高均占满视口：`width: 100vw; height: 100dvh`。
- 页面自身不滚动；聊天消息区内部滚动，预览内容在独立 iframe 或容器内滚动。
- 桌面端默认左右比例建议为 `38% / 62%`。
- 聊天区建议最小宽度 `320px`、最大宽度 `640px`。
- 预览区建议最小宽度 `480px`，优先保证站点预览可用。

#### 左侧聊天区

聊天区严格分为上、中、下三部分：

| 区域   | 建议尺寸              | 内容与行为                                                           |
| ------ | --------------------- | -------------------------------------------------------------------- |
| 顶部栏 | 固定 `52px`           | 返回工作台、项目名称；为后续项目菜单预留右侧操作位                   |
| 对话区 | `1fr`                 | 展示欢迎状态、用户消息、Agent 消息、生成状态和错误状态；独立纵向滚动 |
| 输入区 | 自适应，约 `96-160px` | 多行输入框、发送按钮；输入增长到最大高度后内部滚动                   |

顶部栏：

- 左侧使用 `ArrowLeft` 图标按钮，工具提示为“返回工作台”，点击进入 `/workspace`。
- 中间显示项目名称，超长时单行省略；不要挤压返回按钮。
- 右侧暂时只预留宽度，不必在 MVP 中提供无效按钮。

对话区：

- 初始状态展示一句简短问候和 3 个以内的可点击建议提示，不使用大面积说明卡片。
- 消息内容最大宽度不超过对话区的 `88%`。
- 用户消息靠右或使用浅色实底；Agent 消息靠左并使用更开放的内容布局。
- 新消息到达时，仅当用户接近底部才自动滚动；用户查看历史消息时不强制跳到底部。
- 生成中在最后一条 Agent 消息位置显示明确的进行状态。

输入区：

- 与对话区之间使用 `1px` 顶边界。
- 输入框支持多行，默认 3 行视觉高度，建议最大高度 `120px`。
- 发送使用 `Send` 图标按钮，并提供 `aria-label="发送消息"` 和工具提示。
- 空输入或消息发送中时禁用发送按钮。
- 键盘约定：`Enter` 发送，`Shift + Enter` 换行；使用输入法组合文字时不得误发送。

#### 中间拖拽条

建议使用 `react-resizable-panels` 当前版的 `Group / Panel / Separator` API：

```tsx
<Group orientation="horizontal">
  <Panel defaultSize="38%" minSize="320px" maxSize="640px">
    <ChatPanel />
  </Panel>
  <Separator className="resize-handle" />
  <Panel minSize="480px">
    <PreviewPanel />
  </Panel>
</Group>
```

- 可见分隔线宽 `1px`，实际可点击和拖拽热区至少 `8px`。
- Hover、拖拽和键盘聚焦时显示高对比状态，但不改变布局宽度。
- 拖拽时鼠标样式为 `col-resize`。
- 分隔条必须支持键盘调节，并提供可识别的无障碍标签。
- 可通过 `defaultLayout`、`onLayoutChanged` 和 `localStorage` 保存用户最后一次比例；没有记录时使用默认比例。
- 对聊天区和预览区直接使用像素最小宽度，避免大屏百分比可用、小屏实际宽度却不足的问题。

#### 右侧预览区

第一阶段只提供预览框架和状态占位，不实现文件树或编辑器。

- 顶部预览栏固定 `52px`，左侧标题为 `Preview`，右侧预留刷新按钮。
- 内容区域占满剩余空间，背景与生成的网站画布形成清晰边界。
- 接入 Sandbox 后使用 `iframe` 加载预览 URL，并配置合适的 `sandbox` 权限。
- iframe 建议使用白色背景，避免目标页面透明时继承产品背景。
- 必须设计以下状态：等待首次生成、Sandbox 启动中、预览就绪、加载失败、连接断开。
- 加载失败时提供 `重试` 命令按钮；不要只显示不可操作的错误文本。

## 5. 响应式策略

双栏工作区在小屏上不能继续强行并排：

| 断点             | 布局                                                               |
| ---------------- | ------------------------------------------------------------------ |
| `>= 1024px`      | 可拖拽双栏，默认 `38% / 62%`                                       |
| `768px - 1023px` | 可拖拽双栏，聊天区默认约 `42%`，收紧顶部栏文案                     |
| `< 768px`        | 切换为 `Chat / Preview` 顶部标签页，一次显示一个面板，不展示拖拽条 |

移动端要求：

- 顶部标签使用等宽分段控件，在 Chat 和 Preview 之间切换。
- 切换面板时保留聊天滚动位置、输入内容和预览状态。
- 输入区使用 `env(safe-area-inset-bottom)` 处理底部安全区。
- 使用 `100dvh`，降低移动浏览器地址栏变化造成的跳动。

## 6. 组件边界建议

```text
App
|- AppRouter
|  |- HomePage
|  |- WorkspacePage
|  |  |- AppHeader
|  |  |- ProjectGrid
|  |  `- EmptyProjectsState
|  `- ProjectPage
|     |- ProjectWorkspace
|     |  |- ChatPanel
|     |  |  |- ChatTopBar
|     |  |  |- MessageList
|     |  |  `- ChatComposer
|     |  |- PanelSeparator
|     |  `- PreviewPanel
|     |     |- PreviewTopBar
|     |     `- SandboxFrame
|     `- MobilePanelTabs
`- shared UI
   |- IconButton
   |- Button
   |- Tooltip
   `- StatusView
```

页面组件负责路由参数和数据获取；面板组件负责布局；消息、输入和 Sandbox 状态组件只处理各自领域，避免把所有逻辑继续堆在当前 `app.tsx` 中。

## 7. 核心 UI 状态

| 功能       | 状态                                        |
| ---------- | ------------------------------------------- |
| 创建项目   | idle、creating、error                       |
| 对话历史   | empty、loading、ready、error                |
| Agent 生成 | idle、queued、streaming、failed、completed  |
| 消息提交   | editable、submitting、disabled              |
| Sandbox    | idle、starting、ready、disconnected、failed |
| Preview    | placeholder、loading、ready、error          |

不同状态应在原区域内切换，避免加载时整体布局跳动。错误状态需要给出本区域可执行的恢复动作。

## 8. 实现依赖建议

当前已有：

- React 19
- Vite 6
- TypeScript
- Tailwind CSS 4
- `lucide-react`

建议新增：

- `react-router-dom`：页面路由与浏览器历史记录。
- `react-resizable-panels`：项目页双栏和键盘可访问的分隔条。

暂不需要引入全局状态库。页面切换状态可由路由管理，面板比例由本地存储管理，后续服务端数据可根据实际请求方案再决定是否接入数据缓存库。

## 9. MVP 验收标准

- 首页的 `进入工作台` 能进入工作台。
- 工作台同时具备页面标题、创建项目按钮和空项目状态。
- 点击创建项目后能进入带唯一 `projectId` 的项目编辑器。
- 项目编辑器在桌面端显示聊天区、拖拽条和预览区，且占满视口。
- 聊天区顶部返回操作、中部消息列表和底部输入框始终保持三段结构。
- 拖动分隔条不会导致聊天区或预览区小于其可用最小宽度。
- 返回工作台后再次进入项目，页面导航和浏览器前进/后退行为正常。
- 小于 `768px` 时项目编辑器改为 Chat / Preview 单面板切换，不产生横向滚动。
- 所有图标按钮均有可访问名称、键盘焦点态和工具提示。
- 空状态、加载状态和错误状态不会改变主要布局尺寸。

## 10. 后续扩展位置

第一阶段布局应为以下能力保留扩展空间，但不提前展示空控件：

- 聊天顶部栏：项目设置、会话切换、运行状态。
- 聊天消息流：工具调用、审批请求、构建和测试结果。
- 预览顶部栏：刷新、响应式视口切换、在新窗口打开、发布。
- 项目编辑器：文件树、代码编辑器、版本历史。
- 工作台：项目搜索、排序、模板和团队空间。

扩展时优先在现有顶部栏增加模式切换或菜单，不应压缩对话输入区和预览画布的核心空间。
